# PRD: 블로그 전문 검색 (Full-text Search)

> **상태:** Draft  
> **작성일:** 2026-05-13  
> **우선순위:** High

---

## 1. 개요 (Summary)

방문자가 블로그 포스트 제목, 본문, 태그를 키워드로 즉시 검색할 수 있도록, 빌드 타임에 생성한 검색 인덱스를 기반으로 클라이언트 사이드 전문 검색 기능을 제공한다.

## 2. 문제 정의 (Problem Statement)

- 포스트가 늘어날수록 원하는 글을 찾으려면 목록 전체를 스크롤해야 함
- 태그 클릭으로는 복합 조건(예: "React + TypeScript 관련 글")을 표현할 수 없음
- 정적 배포 환경이므로 서버 사이드 검색 API를 붙일 수 없음

## 3. 목표 (Goals)

- [ ] 검색어 입력 후 50ms 이내에 결과 표시 (클라이언트 사이드)
- [ ] 제목, 요약, 태그, 본문 전체 대상 검색
- [ ] 검색 결과에 매칭 키워드 하이라이트
- [ ] 검색창을 Header에서 단축키(`Cmd/Ctrl + K`)로 열 수 있음

**범위 밖 (Non-goals):**

- 서버 사이드 검색 (정적 배포 환경)
- 오탈자 교정(fuzzy search) — 1차 버전에서 제외
- 검색 기록 서버 저장

## 4. 사용자 시나리오 (User Stories)

```
As a 블로그 방문자,
I want to 키워드로 포스트를 검색하고,
So that 관심 있는 글을 빠르게 찾을 수 있다.
```

```
As a 키보드 중심 사용자,
I want to Cmd+K로 검색창을 열고,
So that 마우스 없이 빠르게 검색할 수 있다.
```

## 5. 기능 요구사항 (Functional Requirements)

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| F-01 | 검색창은 모달(오버레이) 형태로 열림 | Must |
| F-02 | 입력 즉시(debounce 150ms) 결과 목록 업데이트 | Must |
| F-03 | 결과 없음 시 "결과가 없습니다" 안내 표시 | Must |
| F-04 | 결과 클릭 시 해당 포스트 페이지로 이동 | Must |
| F-05 | 매칭 키워드를 `<mark>` 태그로 하이라이트 | Should |
| F-06 | `Cmd/Ctrl + K` 단축키로 모달 열기/닫기 | Should |
| F-07 | `Esc` 키로 모달 닫기 | Must |
| F-08 | 태그 필터와 검색어 조합 가능 | Nice-to-have |

## 6. 비기능 요구사항 (Non-functional Requirements)

- **성능:** 검색 인덱스는 빌드 타임에 생성, 런타임 번들에 포함 (포스트 100개 기준 인덱스 크기 < 500KB)
- **접근성:** 모달에 `role="dialog"`, `aria-label`, 포커스 트랩 적용
- **SEO 영향:** 검색 모달은 클라이언트 전용, 정적 HTML에 영향 없음

## 7. 설계 방향 (Design Direction)

### 아키텍처 결정

서버 없는 정적 환경이므로 **빌드 타임 인덱스 생성 + 클라이언트 사이드 검색** 방식을 채택한다.

| 라이브러리 | 채택 여부 | 이유 |
|-----------|-----------|------|
| [FlexSearch](https://github.com/nextapps-de/flexsearch) | ✅ 추천 | 경량(~6KB), 한국어 토크나이징 지원, 빠른 검색 |
| Fuse.js | 검토 | fuzzy search에 강하나 한국어 분절 약함 |
| MiniSearch | 검토 | 가볍고 빠르나 FlexSearch 대비 한국어 지원 미흡 |

### 데이터 흐름

```
빌드 타임:
  virtualPostsPlugin (vite.config.ts)
    └── 기존 Post[] 데이터에 검색 인덱스용 plainText 필드 추가
          (HTML 태그 제거한 순수 텍스트)
    └── virtual:posts 모듈에 포함

런타임:
  SearchModal 마운트
    └── FlexSearch.Index 초기화 (posts 배열로 인덱스 구축)
    └── 사용자 입력 → index.search(query) → 결과 Post[] 렌더링
```

### 파일 변경 예상 목록

| 파일 | 변경 유형 | 설명 |
|------|-----------|------|
| `vite.config.ts` | 수정 | Post 데이터에 `plainText` 필드 추가 (HTML → 텍스트 변환) |
| `src/types/index.ts` | 수정 | `Post` 타입에 `plainText: string` 추가 |
| `src/components/SearchModal.tsx` | 신규 | 검색 모달 컴포넌트 |
| `src/components/Header.tsx` | 수정 | 검색 버튼 추가, `Cmd+K` 이벤트 리스너 |
| `src/hooks/useSearch.ts` | 신규 | FlexSearch 인덱스 초기화 및 검색 훅 |

## 9. 성공 지표 (Success Metrics)

- 검색 입력 후 결과 표시까지 < 50ms (Chrome DevTools 기준)
- 인덱스 포함 후 JS 번들 증가량 < 30KB (gzip)
- 포스트 100개 기준 검색 정확도: 제목 완전 일치 100% 히트

## 10. 의존성 & 위험 (Dependencies & Risks)

| 항목 | 유형 | 설명 |
|------|------|------|
| FlexSearch 패키지 | 의존성 | `pnpm add flexsearch` 필요 |
| 한국어 형태소 분석 | 위험 | FlexSearch는 공백 기반 토크나이징 → 조사 포함 검색어 부정확 가능성. 1차에서는 허용 |
| 번들 크기 증가 | 위험 | 포스트 전문(plainText) 포함 시 번들 크기 증가. 100KB 초과 시 lazy import 검토 |
